# Renderide parity audit

Read-only audit of fork `DoubleStyxx/Renderide` at `aafcb72035fa2bc24b860cb2c6c3d4ece5aa49c3` (master, 2026-10-23, wgpu 30 bump) against [Renderide candidate requirements](https://github.com/Yellow-Dog-Man/Renderite.Candidates/blob/main/Candidates/Renderide.md). Renderer code was not modified. Upstream `DoubleStyx/Renderide` was not touched.

Every bullet in that document that carries ✅, ⚠️, 🔜, 🛑, or 🗨 is a row. Statuses were checked in the Rust renderer, WGSL, XR/input, IPC, assets, video, render graph, the C# generator and `RenderideMod`, and the tests. The document was not treated as evidence.

## How to read the table

- **Verified status** is what the code does. `Doc wrong` means the marker does not match the code; the gap says whether the truth is implemented, partial, or missing.
- **Effort** on a finished row is `S` and the gap is empty. On a gap it is the remaining work: S under a day, M a few days, L larger than that, XL a new subsystem.
- **Priority** follows the document: Required, Ideal, or Nice-to-have. Overview rows use Required for the claimed baseline, Ideal for future shading languages and mobile, and Nice-to-have for the hardware note. The post 'not required' AA block is Nice-to-have. The scene-model alternative is Ideal.
- **Owner** is Shader for rendering features and Bridge for input, IPC, interop, windows, textures, video, bootstrap, and platform.
- The 1,000-line Rust module gate (`crates/renderide/tests/architecture_layers.rs` `renderer_source_modules_stay_under_line_limit`) does not apply to this markdown file.

### Top 10 gaps by priority and impact

1. **Skinned meshes are not frustum or Hi-Z culled** (Nice-to-have row, Required performance impact). `compute_cached_cull` returns immediately for skinned renderers, so off-screen avatars still deform and draw.
2. **Camera clear None and Depth-only do not preserve attachments** (Required). Skybox and color clears draw a background, but every forward view `LoadOp::Clear`s color and the depth prepass always clears depth. Camera stacking into one texture cannot keep the previous camera.
3. **Object and skinned motion blur** (Required). Blur is camera reprojection from depth. There is no velocity buffer from transforms or skinning.
4. **LOD cross-fade** (Required LOD, Ideal blend). `cross_fade` is stored and never drives a blend or dither.
5. **Unity performance parity is unmeasured** (Required). Criterion and framebench exist. Nothing compares a Resonite-like scene to Unity.
6. **VR mirrors are extra full views** (Required mirrors, Ideal single-pass). Oblique render-to-texture works. A stereo portal is two mono rectangles, not one multiview pass, and there is no stencil portal.
7. **Camera double-buffering is a sampling flag** (Required). One color image per render texture. `AllowPreviousContents` does not ping-pong.
8. **Gaussian splat uploads are placeholders** (called out under pipeline control, not its own marker). `on_gaussian_splat_*` acks and does not draw. Content that is splats will not appear.
9. **IME preedit is dropped** (Required). Commits are forwarded. `composition_active` is hardcoded off.
10. **Touch is not proxied** (Required). The IPC vector is always empty. Gamepad and pen are the same shape, at Nice-to-have priority.

### Dependencies between gaps

- **Mirrors.** Stencil compare, ops, and masks already exist, so a stencil portal can be a mask pass plus the existing oblique camera (`camera/portal.rs`). It does not need new stencil enums. Single-pass VR mirrors depend on the primary multiview path (`MULTIVIEW`, two-layer swapchain) being used for portal targets. Today `CameraPortalSourceViewPlans::stereo` splits the RT into two mono rects. Clip is an oblique near plane, not a separate hardware clip-plane feature.
- **Motion blur.** Object blur needs a velocity buffer. `render_graph/blackboard.rs` reserves the slot; `motion_blur.wgsl` `velocity_from_depth` does not read object motion. Skinned blur depends on that buffer plus previous positions from `GpuSkinCache` (the cache already skips unchanged deforms via `DeformSignature`). Camera blur does not.
- **HDR display.** Scene color is already `Rgba16Float` and bloom runs before tonemap, so the scene path is not the blocker. Display HDR needs a swapchain format other than the 8-bit default from `surface.get_default_config`, and tonemap must stop mapping to 0..1 sRGB (`config/types/post_processing/tonemap.rs`).
- **LOD cross-fade** depends only on the stored `cross_fade` flag plus drawing two LOD levels. It does not depend on stencil or velocity.
- **SSR** can use the existing depth buffer, the GTAO normal prepass, and HDR color before tonemap. The camera flag is already decoded and unused. **Screen-space GI** would share that G-buffer and does not replace probe/SH2 GI.
- **Foveation** depends on an upstream wgpu variable-rate feature, or a quad-view path that would fork the multiview swapchain. Neither exists.
- **Shared shadow maps** depend on the existing `ShadowFramePlan` atlas. `prepare_shadow_frame_for_views` appends a set per `ViewId`, so mirrors and extra cameras repeat point and spot renders. Deduping is a planning change, not a new shadow technique. Hard and soft maps themselves already work (3x3 PCF).
- **Double-buffered cameras** depend on `GpuRenderTexture` growing a second color image. `RenderTextureSelfSampling::AllowPreviousContents` is already plumbed and is forced off when the camera also runs post.
- **Wave intrinsics** depend on requesting `wgpu::Features::SUBGROUP`. Naga validation already allows subgroup ops; no shader uses them. Clustered light and Hi-Z are the consumers.
- **Skinned culling** can call the bone-bounds AABB already built for probe selection (`world_mesh/culling/geometry.rs`) from `compute_cached_cull`, then share that result across material slots the way static meshes do.
- **Dynamic VR/desktop switching** depends on recreating `RenderTargetMode`. View planning already separates desktop, HMD, and offscreen, so the gap is session lifetime, not a new culling scheme.
- **Clear modes** should land before mirror and stacked-camera polish. A portal or stacked camera that asks for clear-none currently still clears.
- **Mesh shaders** are not a dependency of any other row. The vertex/fragment path is the fallback the doc asks for, and it is the only path.

### Per-gap proposals (top 15)

Constraint for every PR: no per-frame heap allocation on the render hot path. Reuse the existing patterns: `ShadowCasterPlanScratch`, draw-prep command cache, `upload_arena`, mesh-deform scratch, and skin-cache arenas. Benchmarks are Criterion (`cargo bench -p renderide-bench`, groups in `crates/renderide-bench/benches/cpu_hot.rs`), `renderide-framebench`, or a `renderide-test` golden (`goldens/`).

1. **Skinned frustum and Hi-Z cull.** One PR. Feed the existing skinned AABB into `compute_cached_cull` and reuse it across slots. Bench: extend Criterion `culling/homogeneous_clip_aabb` with a skinned batch. Framebench a scene of off-screen skinned meshes and show draw count drop. Do not allocate a bounds vec per renderer per frame; store the AABB on the renderer row.
2. **Clear-mode load ops.** One PR. Choose color and depth `LoadOp` from `CameraClearMode` for main and offscreen views. Golden: two cameras in one RT, the second with clear none, first camera's pixels survive. No new attachments.
3. **LOD cross-fade.** One PR. When `cross_fade` is set, emit two LOD draws with a dither or opacity from the existing transition height. Golden: a fading LOD group. Bench: framebench the extra draw, and a Criterion test that the fade path does not allocate the draw list.
4. **Rigid object velocity.** One PR. Write a velocity MRT or a packed RG16 target from the previous model matrix during the forward pass, and sample it in `motion_blur.wgsl`. Keep the camera path. Framebench desktop motion blur. Previous matrices live on the draw item, not in a new `Vec` per frame.
5. **Skinned velocity.** Follows PR 4. Store previous skinned positions in the skin-cache arena (the signature skip already knows when they did not change) and export a velocity. Framebench a deforming mesh with blur on. Do not clone the position buffer per frame.
6. **Render-texture ping-pong.** One PR. Second color image on `GpuRenderTexture`, swapped when the double-buffer flag is set. Golden: a camera sampling its own RT shows the previous frame, including with post disabled as today. Memory is steady-state, not allocated when the flag flips every frame.
7. **Single-pass VR mirrors.** Follows PR 2 if portals use clear-none. One PR to render `CameraPortalMode` into a multiview RT using the existing oblique matrix, instead of `stereo` split rects. Framebench one mirror in stereo and compare GPU time to the split path. Stencil portals are a separate later PR (mask pass using existing stencil state).
8. **IME preedit.** One PR. Handle `Ime::Preedit`, fill `composition_active` and `composition_text`, keep commit on `type_delta`. Unit test the snapshot. No per-frame string alloc when IME is idle.
9. **Touch and multi-touch.** One PR. Map winit touch contacts into the existing `touches` vec, reused and cleared. Pressure can be a follow-up if the event carries it. Unit test two contacts. Gamepad and pen are separate small PRs on the same snapshot struct.
10. **Native ASTC and wider subregion uploads.** One Bridge PR: stop returning `None` for ASTC in `map_host_format` when `TEXTURE_COMPRESSION_ASTC` is set, keep the RGBA8 decode fallback. Second PR: subregion path for block formats where the rect is block-aligned. Bench upload bytes in the asset worker, not the frame. Do not decode ASTC on the submit thread.
11. **Share point and spot shadow views across cameras.** One PR inside `prepare_shadow_frame_for_views`: key shadow views by light and render space, not only `ViewId`. Framebench a secondary camera plus a mirror and show atlas layer count. Reuse `ShadowCasterPlanScratch`.
12. **Host lighting falloff.** One PR. A small curve texture or extra `GpuLight` coefficients sampled from `distance_attenuation`'s call site, defaulting to the current BiRP curve so goldens stay put. Golden a point light. No per-frame curve rebuild.
13. **HDR swapchain output.** One PR after a tonemap flag: request a float or HDR10 surface when the adapter allows it, and add a tonemap mode that does not clamp to 8-bit sRGB. Framebench present bandwidth. Fall back to the current sRGB swapchain.
14. **Runtime desktop/VR target switch.** One Bridge PR. Rebuild `RenderTargetMode` without restarting the process, using the existing view-plan split. Framebench is the wrong tool; a session test that desktop frames resume after XR drop is the check. Do not allocate the view list differently per frame.
15. **Gaussian splat draw path, scoped.** IPC already acks uploads. One PR: upload the buffer for real and draw a single unlit point-splat pass after transparents, no SH yet. Golden a tiny splat. Keep the upload on the asset worker and the draw on the existing point topology. This is larger than a week if SH and sorting are in scope; the first PR should not be.

Rows that are `Doc wrong` only because the feature is already implemented (shadow atlas, unlimited skinning, oblique mirrors, hard/soft PCF) do not need feature PRs. Update the candidate write-up instead.
